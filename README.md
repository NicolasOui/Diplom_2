# Автотесты для API Stellar Burgers

Язык **Java**, фреймворк **RestAssured**, отчет в **Allure**, оптимизация кода через **Lombok**.

---

## 🛠️ Стек технологий

* **Java 11** — основной язык разработки.
* **JUnit 4** — фреймворк для написания и запуска тестов.
* **RestAssured** — библиотека для отправки HTTP-запросов и автоматической сериализации POJO.
* **Lombok** — библиотека для автоматической генерации boilerplate-кода (геттеры, сеттеры, конструкторы).
* **Allure Report** — инструмент для генерации наглядных отчетов о прохождении тестов.
* **Maven** — система сборки проекта.

---

## 📂 Структура проекта

* `src/main/java/.../models/` — POJO-модели для отправки данных, оптимизированные с помощью Lombok (`CreateUser`, `LoginUser`, `Order`).
* `src/main/java/.../api/` — API-клиенты и инфраструктура:
    * `CreateUserSteps` — класс для работы с пользователем (регистрация, логин, удаление) с автоматической сериализацией RestAssured.
    * `OrderSteps` — класс для работы с заказами и ингредиентами.
    * `Endpoints` — константы со всеми URL-адресами эндпоинтов.
    * `RandomDataUser` — генератор уникальных данных пользователей на основе timestamp.
* `src/test/java/.../tests/` — тестовые классы:
    * `BaseTest` — базовый класс с настройкой `baseURI` и автоматической очисткой данных в `@After` по токену.
    * `CreateUserTest` — тесты регистрации пользователя (позитивные и негативные кейсы).
    * `LoginUserTest` — тесты авторизации пользователя.
    * `OrderTest` — тесты создания заказа (с авторизацией, без, с ингредиентами и без них).

---

## 🧪 Тест-кейсы

### 1. Создание пользователя (`CreateUserTest`)
* Успешное создание уникального случайного пользователя.
* Проверка структуры и заполненности полей ответа при успешной регистрации.
* Ошибка при попытке зарегистрировать пользователя с уже существующим email (код 403).
* Ошибка при создании пользователя без обязательного поля `name` (код 403).
* Ошибка при создании пользователя без обязательного поля `password` (код 403).

### 2. Логин пользователя (`LoginUserTest`)
* Успешная авторизация существующего пользователя (код 200) и получение JWT-токенов.
* Ошибка авторизации при вводе неверного пароля (код 401).

### 3. Создание заказа (`OrderTest`)
* Успешное создание заказа авторизованным пользователем с валидными ингредиентами.
* Успешное создание заказа неавторизованным пользователем.
* Ошибка при попытке создать заказ без передачи ингредиентов (код 400).
* Обработка ошибки сервера при передаче некорректного (невалидного) хеша ингредиента (код 500).

## 🚀 Запуск тестов и генерация отчетов

### Локальный запуск тестов:
Для очистки старых сборок и запуска всех тестов выполнить в терминале команду:
```bash
mvn clean test
```

### Просмотр Allure-отчета:
Результаты тестов в папке `target/allure-results`. Для генерации и открытия HTML-отчета в браузере выполнить:
```bash
allure serve allure-results
```
